# 独立开发者免费云端架构选型指南：数据库、部署与存储

对于独立开发者和初创团队而言，如何在产品初期以零成本或极低成本构建高可用、高性能且具备弹性的云端架构，是决定项目能否快速验证并生存下去的关键。

当前的云计算生态（尤其是 Serverless 和边缘计算的兴起）为我们提供了极为慷慨的免费额度。本文将围绕核心数据库、部署平台和对象存储三大维度，为你拆解当前最适合独立开发者的免费云端架构方案。

---

## 一、 核心数据库选择 (Database)

数据库是应用的心脏。在选择免费数据库时，我们不仅要看容量，更要看计费模型（如请求数、RU限制）、地理位置延迟以及开发体验。

| 数据库选项        | 兼容语法   | 永久免费额度                  | 核心优势与最佳适用场景                                                                                                                             | 推荐部署区域                   |
| :---------------- | :--------- | :---------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------- | :----------------------------- |
| **CockroachDB**   | PostgreSQL | 10 GB 空间<br>每月 1000万 RU  | **空间最大**。完美支持复杂数据类型（如处理空间坐标轨迹的 JSONB），严苛的 RU 计费机制能倒逼产出高标准 SQL（如使用精确的部门 ID 而非名称进行聚合）。 | 亚太地区<br>(新加坡 / 东京)    |
| **TiDB Cloud**    | MySQL      | 5 GB 空间<br>无严苛请求数限制 | **最平滑的迁移体验**。对传统关系型数据库操作高度兼容，无需操心复杂的查询计费，适合常规业务系统的快速搭建。                                         | 亚太地区<br>(新加坡 / 东京)    |
| **Cloudflare D1** | SQLite     | 5 GB 空间<br>每日 500万次读取 | **物理级零延迟**。跑在边缘节点上，与前端部署同处一个计算网络，极致适合读多写少的高频访问场景。                                                     | 边缘节点<br>(跟随用户就近分配) |

### 数据库选型深度解析

1. **CockroachDB (Serverless)**
   - **适用场景**: 强事务性、需要存储大量复杂 JSON 数据（JSONB）的 SaaS 应用。
   - **说明**: CockroachDB Serverless 采用 RU (Request Unit) 计费。一次低效的 Full Table Scan（全表扫描）可能会瞬间消耗大量 RU。这要求开发者必须建立良好的索引习惯，编写精准的 SQL 语句。

2. **TiDB Cloud (Serverless)**
   - **适用场景**: 传统 MySQL 用户，不想花时间学习 PostgreSQL/SQLite 特性的项目。
   - **说明**: TiDB 对 MySQL 协议有极高的兼容性，开发工具链成熟。由于免费版无严苛的请求数计费阻碍，是新手和快速原型的首选。

3. **Cloudflare D1**
   - **适用场景**: 配合 Cloudflare Worker/Pages 搭建的超轻量、超高频、读多写少的应用（如博客评论系统、配置管理中心、轻量监控等）。
   - **说明**: 由于 D1 运行在 Cloudflare 边缘端，其写操作需要同步回主节点，写延迟相对读延迟会稍高，且不支持复杂的传统 SQL 特性（如触发器、复杂的存储过程）。

4. **Supabase**
   - **适用场景**: 移动端 App、单页应用 (SPA) 等需要快速上线且不想自己写复杂 Auth 逻辑的项目。
   - **说明**: 免费版有 500 MB 的空间限制，且如果项目长时间无流量（通常为 1 周），数据库服务会被暂停，需要手动登录控制台重新唤醒。

## 二、 部署平台选择 (Deployment)

Serverless 部署平台让开发者无需再为服务器的运维、安全更新和扩容烦恼。当前最主流的两大选择各有千秋：

- **Vercel**
  全栈开发体验的标杆，对 SvelteKit 框架的支持最为完善且零配置。免费版允许进入后台设置，将运行后端逻辑的 Serverless 函数区域（Function Region）从美国手动切换为 **香港 (hkg1)**，大幅降低国内网络握手延迟。
- **Cloudflare Pages**
  边缘计算的绝对主力。提供无限流量、无限带宽的慷慨额度。静态资源与后端逻辑全部推送到全球各地的边缘节点执行，天然具备防高并发冲击的能力，国内网络访问速度极速且稳定。

## 三、 文件与图片存储选择 (File Storage)

对于图床、用户上传的附件或静态资源，一个稳定且便宜的对象存储是必不可少的。

- **Cloudflare R2**
  目前图床与大文件存储的**唯一推荐**。提供每月 10 GB 的免费存储空间，核心杀手锏是**出站流量（Egress）完全免费**。它全面兼容 AWS S3 的 API 规范，能彻底替代国内访问极不稳定的 GitHub Raw 方案，防止流量侧的意外扣费。

## 四、 综合选型：黄金组合架构推荐

根据不同的业务场景，这里推荐三套黄金组合架构，帮助你在性能、开发效率和成本之间取得平衡：

### 1. 高阶扩展旗舰版 (推荐)

> **Vercel (香港) + CockroachDB (新加坡) + Cloudflare R2**

- **优势**: 兼顾了 Vercel 极佳的工程化开发体验、极低的大陆直连延迟，以及 CockroachDB 提供的超大存储冗余和高级 PostgreSQL 生态支持（如复杂查询、JSONB 索引等）。
- **适用**: 中大型 SaaS 项目、需要复杂业务逻辑与海量数据处理的应用。

### 2. 物理零延迟边缘版

> **Cloudflare Pages + Cloudflare D1 + Cloudflare R2**

- **优势**: 流量、运算与数据全部收拢在同一个底层云原生生态内。消灭了跨洋跨机房的通信损耗，是最具抗压能力和访问速度上限的纯粹闭环体系。
- **适用**: 高频读访问、全球加速需求高的轻量化 Web 应用或 API 接口。

### 3. 传统极速舒适版

> **Vercel (香港) + TiDB Cloud (新加坡) + Cloudflare R2**

- **优势**: 拥有全套熟悉的 MySQL 开发体验，绕开了复杂严苛的计费策略约束，是独立开发者上手速度最快、试错成本最低的实战方案。
- **适用**: 传统 Web 应用、快速验证的商业项目。

## 五、 架构演进与避坑指南

1. **冷启动问题**
   Serverless 函数在没有请求时会进入休眠，首次请求会触发冷启动。将 Vercel 的部署区域设置为 hkg1 (香港)，并确保你的数据库也部署在亚太（新加坡或东京），可以最大程度减少因地理跨度导致的冷启动网络延迟。
2. **连接池溢出**
   Serverless 环境下每个请求可能都会创建一个新的数据库连接，高并发时容易将数据库的连接数撑爆。务必使用数据库自带的 Connection Pooling (如 Supabase 的 PgBouncer 或 CockroachDB 的连接池代理)。
3. **备份与灾备**
   虽然免费服务很香，但依然要做好定时备份。可以通过 GitHub Action 挂载定时任务，使用命令行工具将数据库导出并备份到 Cloudflare R2 中，确保数据安全无限制。
